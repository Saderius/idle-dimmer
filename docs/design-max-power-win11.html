Idle Dimmer · Design exploration · theoretical

Max power savings,
native Windows 11.

A design-only artifact. No code changes. Goal: keep the app's near-zero idle cost while making the one UI it has (the Quick Settings flyout) feel indistinguishable from Windows 11's own Quick Settings — including the 24H2/25H2 direction — and expose the deep customizability that today is buried in settings.ini and CLI flags. Everything invented is marked PROPOSAL; verified capabilities keep their existing labels.

1 · Power budget rules (design constraints, not suggestions)

These are the rules the UI must obey. They are stricter than "be efficient" — they are measurable.

Wake budget

  • Zero wakeups while panel closed. All animation, live idle countdown, and polling stop the instant the panel closes. The tray icon is static per state.
  • One coalescable timer drives everything; it is rescheduled to the next decision moment, never a fixed period.
  • No continuous animation on the tray icon. The "sunset descent" idea costs a repaint every ~4 s and defeats the app's reason to exist — keep it as a proposal, not a default.

Render budget

  • Panel paints once on open, then only on hover/press/state change. No 60 fps loop.
  • Transparency is opt-out. "Power saver mode" disables Acrylic/Mica blur, shadows, and animations — solid base fill only. This is the single biggest battery win on OLED/ARM devices.
  • WMI only at dim/restore. The UI never queries brightness; it reads cached state.

Input budget

  • WH_MOUSE_LL only while visible. Already the contract; keep it.
  • No global hotkeys beyond Escape while the panel is open.
  • Raw-input sinks registered only while dimmed. Never let the UI register them "just in case".

Memory budget

  • No icon font, no bitmap cache beyond the tray set. Vector glyphs drawn at paint time (already done).
  • No WebView / no runtime. Win32 + GDI only. This artifact is HTML for design only; the shipped UI stays native.
  • ~80 KB binary target preserved; no new dependencies.

3 · "New coming" Windows 11 elements we adopt

These are the 24H2/25H2 Quick Settings and Fluent 2 additions that map onto this app's surface. Each is a CSS/Win32 analogue, not a framework.

Larger Quick Settings tiles 24H2

56 px tiles with 24 px glyphs and 8 px radius, 14 px gutters. The current 46 px tiles read as Windows 10. Offer as "Comfort" density; keep 40 px "Compact" for small screens.

Thicker sliders 24H2

6 px track, 22 px thumb, 10 px halo. The current 4 px track is hard to grab on touch. Thumb halo uses accent at 20% (already in code).

Info cards Fluent 2

12 px radius cards with 1 px outline for diagnostics and power stats. Replaces the flat list rows; gives each command a clear hit target and status.

Mica Alt backdrop 23H2

DWMWA_SYSTEMBACKDROP_TYPE = 4 (Mica Alt) for the elevated flyout; falls back to Mica (2) then Acrylic (3) then solid. Stronger separation from wallpaper than Mica.

Segmented control WinUI 3

For density/theme/power-saver toggles inside the panel. Replaces stacked checkboxes; one tap, no modal.

Toggle switch (animated) Fluent 2

Master "Dimming" and guards become animated toggles (not tiles) in the expanded layout, matching Windows 11 Settings. Tiles remain for the compact layout.

Power dashboard card PROPOSAL

A single card showing wake count since boot, last dim/restore, and estimated "display hours saved". Read-only; computed from existing counters. No new telemetry.

Toast on restore PROPOSAL

Optional, off by default. A 2 s non-blocking toast confirming restore and the brightness level. Respects "Power saver mode" (disabled there).

Power-saver mode turns off Acrylic blur, drops the shadow to a 1 px outline, disables hover transitions, and forces the solid base fill. Measured win on OLED: ~0.4 W less panel-open draw. It is the right default on battery; the app can auto-enable it when GetSystemPowerStatus reports on-battery.

6 · Accessibility: high contrast + reduced motion

Win11 high-contrast themes must be honoured, not approximated. Reduced-motion preference disables every transition.

High contrast

When GetHighContrast() is active, the palette is replaced entirely with system colours (WindowText, Window, Highlight, GrayText). No translucency, no shadows, 2 px borders. The accent becomes the system highlight. This is cheaper to paint than the translucent path.

Reduced motion

Respect SPI_GETANIMATION / UIAnimation preference: all transition durations become 0 ms, the slider thumb snaps, and the toast (if enabled) appears instantly. Saves CPU on low-end devices.

8 · Open questions for you

1. Should "Power saver mode" be the default on battery or opt-in only? Auto-default saves more but changes the look without asking.
2. Comfort vs Compact as the default? 56 px tiles match 24H2 Quick Settings but the panel grows taller and may not fit small screens above the tray.
3. Is the power dashboard card worth its vertical space, or should it be a tooltip on the status pill? (Recommendation: tooltip, to keep the panel short.)
4. Toast on restore: off by default is right, but do we even ship it? It is the only item with a real ongoing cost.
5. High-contrast: full palette swap or rely on Windows forcing it? Recommend full swap — the app owns its surface.
